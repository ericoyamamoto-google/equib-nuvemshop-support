# Agent Spec: EQUI'B Nuvemshop Customer Support & Order Status Agent

## Overview
The **EQUI'B Nuvemshop Customer Support & Order Status Agent** (`equib-nuvemshop-support`) is an enterprise multi-agent system built with Google's Agent Development Kit (ADK) Python and `agents-cli`. It automates customer support for **EQUI'B**'s e-commerce storefront on **Nuvemshop (Tiendanube)** by handling order status inquiries, shipment tracking (Correios / Jadlog / Melhor Envio), store policy and sizing questions, exchange/support ticket creation, and Human-in-the-Loop (HITL) gated order refunds.

## Assumptions
- Nuvemshop API integrations (`orders`, `shipments`, `tickets`, `refunds`) are mocked with realistic EQUI'B storefront data for deterministic evaluation and local testing, while authenticating API credentials through Google Cloud Secret Manager (`NUVEMSHOP_ACCESS_TOKEN`, `NUVEMSHOP_STORE_ID`) with safe local environment fallback.
- Deployment target is `agent_runtime` (Vertex AI Agent Engine / Runtime) with `github_actions` CI/CD and Terraform Infrastructure as Code (`deployment/terraform/`).

## Language
`python`

## Architecture & Sub-Agents
- **`equib_support_coordinator` (Root Coordinator — Pro Model)**: Orchestrates customer conversations, maintains cross-session memory via `PreloadMemoryTool()` and async background memory consolidation (`asyncio.create_task`), and delegates to specialized sub-agents.
- **`order_investigation_pipeline` (`SequentialAgent`)**:
  1. **`order_lookup_specialist` (Flash Model)**: Queries Nuvemshop order status and carrier tracking milestones.
  2. **`policy_and_catalog_specialist` (Flash Model)**: Checks EQUI'B return/exchange windows (7-day statutory regret right / 30-day size exchange) and product catalog details via persistent knowledge retrieval (`VertexAiSearchTool` + local store policy KB).
- **`resolution_and_refund_specialist` (Pro Model)**: Creates Nuvemshop exchange/support tickets and executes high-stakes financial refunds gated by Human-in-the-Loop confirmation (`require_confirmation`).

## Example Use Cases
1. **Order Status & Tracking Lookup**:
   - *Input*: "Hi! Can you check the status and tracking for my EQUI'B order EQB-1001? My email is marina.silva@example.com."
   - *Expected Output*: Looks up order `EQB-1001`, retrieves tracking code `BR987654321EQ`, reports current transit status and estimated delivery date, and redacts customer PII (`marina.silva@example.com`) in all logs and memory stores.
2. **Guided Error Recovery on Invalid Order Number**:
   - *Input*: "Where is my order #1001?"
   - *Expected Output*: Tool validation catches format mismatch (`#1001` vs `EQB-1001`), returns a structured `recovery_instruction`, and the agent automatically normalizes the ID to `EQB-1001` or guides the user clearly.
3. **Exchange & High-Stakes Refund with Human-in-the-Loop (HITL)**:
   - *Input*: "My order EQB-1002 arrived damaged and I want a full refund of R$ 389.90."
   - *Expected Output*: Verifies order eligibility against EQUI'B store policies and triggers an explicit HITL confirmation hook before executing `process_nuvemshop_order_refund`.

## Tools Required
1. `lookup_nuvemshop_order_status`: Retrieves order details, payment status, fulfillment status, and line items from the mocked Nuvemshop Orders API (`GET /v1/{store_id}/orders`).
2. `track_nuvemshop_shipment_delivery`: Queries carrier tracking events and estimated delivery dates for a Nuvemshop shipment (`GET /v1/{store_id}/orders/{id}/fulfillments`).
3. `search_equib_store_policies_and_catalog`: Searches EQUI'B store policies (returns, exchanges, sizing, care) backed by `VertexAiSearchTool` and persistent store policy storage.
4. `create_nuvemshop_exchange_or_support_ticket`: Creates a structured exchange or support ticket with strict Pydantic schema validation.
5. `process_nuvemshop_order_refund`: Executes a refund on Nuvemshop (`POST /v1/{store_id}/orders/{id}/refunds`), protected by `FunctionTool(..., require_confirmation=...)` and `tool_context.request_confirmation(...)`.

## Constraints & Safety Rules
1. **PII Redaction**: All customer emails, phone numbers, Brazilian CPFs, credit card numbers, and API tokens must be scrubbed via `PIIRedactor` (Google Cloud DLP API + regex fallback) before writing to structured JSON logs or memory.
2. **Human-in-the-Loop Confirmation**: Any refund operation (`process_nuvemshop_order_refund`) or high-value credit above R$ 100.00 must pause for explicit human confirmation (`require_confirmation`).
3. **Zero Hardcoded Secrets**: All API keys and tokens (`NUVEMSHOP_ACCESS_TOKEN`) must be fetched via `google.cloud.secretmanager` or environment injection.
4. **Prompt Injection & Policy Guardrails**: `AgentOpsGuardrailPlugin` (`BasePlugin`) inspects all model requests (`before_model_callback`), model responses (`after_model_callback`), and tool calls (`before_tool_callback` / `after_tool_callback`).
